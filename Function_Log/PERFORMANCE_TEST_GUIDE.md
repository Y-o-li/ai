## 📖 快速开始

### 1️⃣ 打开测试页面
在 Chrome 浏览器中打开 `DOM_performance_test.html` 文件。

### 2️⃣ 等待插件初始化
页面加载后，观察控制台输出：
```
🎯 性能测试页面已加载
📊 等待插件初始化...
✅ 插件已就绪
💡 提示：点击各个按钮运行测试
```

### 3️⃣ 开始测试
使用快捷键或点击按钮运行测试。

---

## ⌨️ 快捷键完整列表

| 快捷键 | 功能 | 说明 | 预期结果 |
|--------|------|------|----------|
| **Ctrl + 1** | 📝 基础煽动性检测 | 测试高危句式识别 | 检测到煽动内容，置信度 >80% |
| **Ctrl + 2** | 🧠 上下文理解（否定句） | 测试否定语境降权 | 置信度显著降低或不检测为煽动 |
| **Ctrl + 3** | ✅ 白名单过滤 | 测试学术/新闻语境 | 正确过滤，不误报 |
| **Ctrl + 4** | 💾 缓存性能测试 | 连续检测 10 次 | 显示加速比和缓存命中率 |
| **Ctrl + 5** | ⚡ 批量 DOM 操作 | 生成 100 个句子 | 展示批量处理性能优势 |
| **Ctrl + R** | 📊 查看性能报告 | 显示完整统计 | 缓存状态、命中率、TTL 等 |
| **Ctrl + C** | 🗑️ 清空所有缓存 | 重置缓存状态 | 准备新一轮测试 |

## 🎯 推荐测试流程

### 标准测试流程（首次使用）

```
步骤 1: Ctrl + C  → 清空缓存

步骤 3: Ctrl + 4  → 再次运行（观察缓存加速效果）
步骤 4: Ctrl + R  → 查看性能报告
```

```

步骤 2: Ctrl + 2  → 验证上下文理解

步骤 4: Ctrl + 5  → 验证批量处理性能
步骤 5: Ctrl + R  → 查看综合报告
```

### 压力测试流程

```
步骤 1: Ctrl + C  → 清空缓存

步骤 4: Ctrl + R  → 查看缓存使用和性能
```

## 📊 测试结果解读

### 测试 1: 基础煽动性检测 (Ctrl+1)

**关注指标**:
- ✅ **检测结果**: 应为"检测到煽动性内容"
- 📈 **置信度**: 应在 80-98% 之间
- 🔍 **匹配词汇**: "消灭"、"敌人"、"一起行动"等
- ⏱️ **耗时**: <5ms（有缓存）或 <20ms（首次）

**示例输出**:
```json
{
  "检测结果": "✅ 检测到煽动性内容",
  "置信度": "92.45%",
  "匹配词汇": "消灭，敌人，一起行动",
  "耗时": "2.34ms"
}
```

---

### 测试 2: 上下文理解 (Ctrl+2)

**关注指标**:
- ✅ **检测结果**: 应为"未检测为煽动"或"检测到（降权）"
- 📉 **置信度**: 应显著低于测试 1（通常 <30%）
- 🔍 **否定词识别**: 应为"已识别"

**示例输出**:
```json
{
  "检测结果": "✅ 未检测为煽动",
  "置信度": "15.23%",
  "否定词识别": "✅ 已识别",
  "匹配项": 2
}
```

---

### 测试 3: 白名单过滤 (Ctrl+3)

**关注指标**:
- ✅ **检测结果**: 应为"正确过滤"
- 📊 **白名单命中**: 应有值（如"研究表明"、"据统计"）
- ❌ **实际匹配**: 应为 0 或很少

**示例输出**:
```json
{
  "检测结果": "✅ 正确过滤",
  "白名单命中": 3,
  "实际匹配": 0
}
```

---

### 测试 4: 缓存性能测试 (Ctrl+4) ⭐ 核心测试

**关注指标**:
- 📈 **加速比**: 应在 5-20x 之间（越大越好）
- 🎯 **缓存命中率**: 第二次测试应 >80%
- ⏱️ **首次检测时间**: <20ms
- ⏱️ **末次检测时间**: <3ms

**示例输出**:
```json
{
  "总迭代次数": 10,
  "首次检测时间": "15.67ms",
  "末次检测时间": "0.89ms",
  "平均时间": "2.45ms",
  "加速比": "17.61x",
  "缓存命中率": "90.00%",
  "缓存大小": "12/500"
}
```

**性能基准**:
- 🟢 **优秀**: 加速比 >10x，命中率 >85%
- 🟡 **良好**: 加速比 5-10x，命中率 70-85%
- 🔴 **待优化**: 加速比 <5x，命中率 <70%

---

### 测试 5: 批量 DOM 操作 (Ctrl+5)

**关注指标**:
- 📊 **总句子数**: 100
- 🔍 **检测到煽动**: 约 60-80（取决于句子）
- 📦 **高亮元素**: 应少于检测到的煽动数（合并效果）
- ⏱️ **总耗时**: <500ms
- ⏱️ **平均每句**: <5ms

**示例输出**:
```json
{
  "总句子数": 100,
  "检测到煽动": 75,
  "高亮元素": 45,
  "总耗时": "234.56ms",
  "平均每句": "2.35ms",
  "DOM 优化": "批量创建 vs 逐个创建"
}
```

**DOM 优化率计算**:
```
优化率 = (检测到煽动 - 高亮元素) / 检测到煽动 × 100%
例如：(75 - 45) / 75 × 100% = 40% 减少
```

## 🛠️ 故障排查

### 问题 1: 插件未加载提示

**现象**:
```
⚠️ 插件未加载，无法执行实际检测
```

**解决方案**:
1. 确保在 Chrome 扩展环境中运行
2. 检查扩展是否已安装并启用
3. 刷新页面重新加载

---

### 问题 2: 缓存命中率低

**现象**: 缓存命中率 <50%

**可能原因**:
1. 每次测试的文本不同
2. 缓存 TTL 过期（5 分钟）
3. 缓存已满被 LRU 淘汰

**解决方案**:
1. 按 `Ctrl + C` 清空缓存
2. 重新运行同一测试多次
3. 检查缓存大小是否接近上限

---

### 问题 3: 性能明显下降

**现象**: 检测时间 >50ms

**可能原因**:
1. 页面打开了太多标签页
2. 内存占用过高
3. 其他扩展冲突

**解决方案**:
1. 关闭不必要的标签页
2. 重启浏览器
3. 在无痕模式测试（仅启用目标扩展）

## 💡 高级技巧

### 技巧 1: 对比测试
```
1. 按 Ctrl + C 清空缓存
2. 立即按 Ctrl + 4 运行第一次（无缓存）
3. 不按任何键，等待 3 秒
4. 再按 Ctrl + 4 运行第二次（有缓存）
5. 对比两次的时间差异
```

### 技巧 2: 压力测试
```
1. 连续按 Ctrl + 5 五次
2. 观察每次的高亮元素数量变化
3. 按 Ctrl + R 查看缓存状态
4. 评估内存管理是否正常
```

### 技巧 3: 实时监控
```
1. 打开浏览器开发者工具（F12）
2. 切换到 Console 标签
3. 运行测试时查看详细日志
4. 观察 Trie 树构建、缓存命中等信息
```
